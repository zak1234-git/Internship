基本要求如下：
0、整体布局，在不改变现有的周围框架下，页面上部为列表部分（列表中设备的个数从获取ap列表的接口中得到），且当设备较多时，可以上下滑动滑条（就是指列表占的位置相对固定，不影响其他部分），且当窗口缩小时也可左右滑动横条，页面下部分为具体的编辑部分，包含下面提到的功能，且和基本信息的信息框保持一致，位于下半部分的页面中央
1、设备列表显示当前子网的G/T设备基本信息（包括设备id，设备名称，设备类型，ip地址，信道，物理带宽，业务带宽，固件版本），并支持跨节点编辑（就是指编辑当前连接的其他设备，而不是只有当前设备）、重启、恢复出厂设置功能按钮。
2、设备列表下方则显示当前编辑的相关设备ID、设备名称设备的基本信息。
3、设备类型、信道、物理带宽、业务带宽都为下拉框。
4、设备类型：G节点(主节点)、T节点(终端节点)。
5、信道：41、125、209、291、375、459、541、625、709、791、1375、1459、1541、1625、1709、1791、1875、1959、2041、2125、2209、2291、2479、2563、2645、2729、2813。
6、物理带宽：20M、40M、80M。
7、业务带宽：20M、40M、80M。
8、业务带宽的设置不能大于物理带宽。
9、如果当前设置的物理带宽小于设备的业务带宽，则做提示框。
10、保存配置按钮则将修改的信息保存到对应设备配置中，如果当前修改的是当前设备的IP地址，则需要重新跳转到访问修改以后的IP地址页面(仪表盘首页)。
11、点击恢复出厂设置与重启按钮需要显示确认框，点击确认以后则需要显示一个缓冲圈等待设备重启或者恢复出厂设置，重启或恢复出厂设置成功以后自动刷新网页跳转到仪表盘首页。（这里和之前的快捷操作一样，先预留接口，后面会实现）
12、支持远程跨节点断开连接。
13、在页面下部的编辑部分有一个设备高级配置的按钮，点击后页面下部就会切换到对应的高级配置的页面，样式这些也是和基本配置保持一致，具体内容等后面提供具体实现
14、相关的api接口如下所示：

URL：/nodes
方法：GET
请求头：Authrization: Bearer <token>
请求参数：无
响应（200 OK）：
json示例：
{
	"status": "success",
	"data": {
		"nodes": [{
			"id": 0,
			"type": 0,
			"name": "Gnode_000",
			"mac": "06:08:10:00:00:21"
			}, {
			"id": 1,
			"type": 1,
			"name": "tnode_001",

			}]
	}
}

URL：/nodes/{id}/basicinfo

请求头：Authrization: Bearer <token>
请求体：json示例

    "type": 0,
    "name": "gnode_01",
    "ip": "192.168.99.1"
    "channel": 2479,
    "bw": 40,

}
响应（200 OK）：
json示例：

    "status": "success"
}
